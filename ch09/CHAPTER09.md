# 또다시 마침내 프로퍼티 

다른 사람 코드 참고하거나 ai가 짜주는 코드볼떄마다. 한번식 나오는 get; set; 이게 뭔지 정말 궁금했다.

일단 클래스의 필드를 private를 선언하는게 좋다고 했다. 데이터가 오염될 수 있기 때문이다. 하지만 그렇게 하면 솔직히 조금 귀찮다.

private는 그냥 접근할 수 없고 메소드를 추가해서 필드에 접근할 수 있게 하고 인스턴스를 할당하고 메소드를 호출해서 값을 쓰거나 가져올거다.

```c#
private int age;

public void SetAge(int value) {
    if (value < 0) age = 0; // 데이터 보호 가능
    else age = value;
}

public int GetAge() {
    return age;
}

// 사용 시: obj.SetAge(20); / Console.WriteLine(obj.GetAge());
```

이렇게 말이다. 전혀 문제 있는 코드가 아니다. 은닉성을 지키며 필드를 읽고 쓰고 있다. 만약 Java를 쓴다면 이게 정석이다.

하지만 c#에는 프로퍼티라는게 존재한다.

### 메소드보다 프로퍼티
----
일단 선언하는 법부터 보자 
``` c#
class 클래스_이름
{
    데이터_형식 필드_이름;
    접근_한정자 데이터_형식 프로퍼티_이름
    {
        get
        {
            return 필드_이름;
        }

        set
        {
            필드_이름 = value;
        }
    }
}
```
특정 키워드가 눈에 띄지 않는가 get과 set 말이다. 내가 그토록 궁금해 했던 키워드들 프로퍼티이다.

get{...}, set{...}을 일컬어 접근자라고 한다. get접근자는 필드로부터 값을 읽어오고 set 접근자는 필드에 값을 할당한다. set 접근자 내부에 value 키워드는 선언한적이 없지만,

c# 컴파일러는 set 접근자의 암묵적 매개변수로 간주하므로 문제가 없다. 이렇게 get set 접근자를 쓰면 
```c#
MyClass obj = new MyClass();
obj.MyField = 3;
Console.WriteLine(obj.MyField);
```
이렇게 메소드를 불러올 필요가 없이 그냥 변수에 값을 넣듯이 '=' 연산자로 값을 읽고 저장이 가능하다. 

또한 단순히 get 접근자만 쓰면 읽기 전용, set 접근자만 쓰면 쓰기 전용 프로퍼티가 된다. 물론 쓰기 전용 프로퍼티는 동작 결과를 확인하기가 어려워 비추천한다.

이제 예제를 만들어 보자 [예제01](01_Property.cs) (예제를 만들고 ai한테 검토를 받으며 알게된건데 관례적으로 필드는 앞에 _를 붙이고 프로퍼티는 대문자로 시작하는게 좋다고 한다.)

캐릭터 생성을 예시로 예제를 짜보았다. 하지만 아직 부족하다. 내가 봐왔던 프로퍼티는 좀더 짧고 간단한 코드로 작성되었었다.

### 자동 구현 프로퍼티
프로퍼티는 데이터의 오염에 대해선 메소드처럼 안전하고 , 다루는 건 필드처럼 간결하다.

하지만 위와 같은 방식은 중복 코드를 작성하고 있다. 단순히 읽고 쓰는데에 아무런 논리가 없다면 더 간단히 쓸수가 있다. 드디어 내가 알고 싶던 형태가 나온다. 
```c#
public class NameCard
{
    public string Name{get; set;}
    public string PhoneNumber{get; set;}
}
```
필드를 선언할 필요도 없고 코드도 획기적으로 줄었다! 심지어 이게 끝이 아니다. C#7.0부터는 자동 구현 프로퍼티를 선언함과 동시에 초기화를 수행할 수 있다.

public string Name{get; set;} = "Unknown"; 이런식으로 말이다. 생성자에 초기화 코드를 작성하는 수고를 덜게 되었다. 

그럼 다시 예제를 만들어보자 앞서 만들었던 코드를 수정하는 식으로 말이다. [예제02](02_AutoProperty.cs)

에제의 길이가 정말 줄어들었음을 확인할수 있다. 가독성도 향샹된 모습을 볼수있다. 이처럼 특별한 로직이 필요없다면 자동 구현 프로퍼티를 이용해 간결하게 작성이 가능하다.

그런데 이게 어떻게 가능할까? 

### 자동 구현 프로퍼티 -2
사실 진짜 필드가 없는건 아니다. 우리가 선언하지도 않았지만 컴파일러가 자동으로 구현해준다. 그러니깐 프로퍼티를 선언하면 그 뒤에서는 맨 처음 이야기 했던 정석적인 코드가 생성되고 실행된다는 말이다.
```c#
// 우리가 쓴 코드
public string Name { get; set; }

// 컴파일러가 만들어내는 실제 코드
private string <Name>k__BackingField; // 컴파일러만 아는 이름을 가진 필드 생성

public string Name 
{
    get { return <Name>k__BackingField; }
    set { <Name>k__BackingField = value; }
}
```
이런 식으로 말이다. 저렇게 생성된 필드는 우리가 접근할 수 없다. 우리가 프로퍼티를 호출할 떄마다 컴파일러가 알아서 저 숨겨진 필드에 값을 넣고 뺴준다.

덕분에 우리는 편하게 작업을 할 수 있게 되었다. (컴파일러야 고마워!)

### 프로퍼티와 생성자
객체를 생성할 때 우리는 매개변수를 입력받아 객체의 각 필드를 초기화했었다. (바로 위 예제도 그랬었고)

프로퍼티를 이용한 초기화도 가능하다. 
```C#
클래스_이름 인스턴스 = new 클래스_이름() 
{
    프로퍼티1 = 값,
    프로퍼티2 = 값,
    프로퍼티3 = 값.
};
```
이런 형식이다. 이와 같이 객체를 생성할 때 프로퍼티 = 값 목록에 객체의 모든 프로퍼티가 올 필요는 없다. 초기화하고 싶은 프로퍼티만 넣어서 초기화하면 된다.

매개변수가 있는 생성자는 어떤 필드를 생성자 안에서 초기화할지 미리 고민했었지만 그럴 필요가 없다. 

또 하나 배웠으니 써먹어 봐야지 예제로 넘어가자 [예제03](03_PropertyConstructor.cs) 

앞서 썻던 예제를 한번더 수정했다. 점점더 간결하고 읽기 쉽게 예제가 바뀌는 걸 볼 수 있다.

### 초기화 전용 자동 구현 프로퍼티 
의도치 않게 데이터가 오염되는 일은 종종 있다. 그래서 여러 장치가 있다. readonly 필드, readonly 구조체, 튜플 등이 있다. 하지만 프로퍼티는 읽기 전용으로 선언하는  방법이 조금 불편하다.

생성자를 통해 필드를 초기화하고 그 필드에 접근하는 프로퍼티는 get 접근자만 갖도록 해야한다. 
```c#
class Transaction
{
    public Transaction(string _from, string __to, int _amount)
    {
        from = _from; to = _to; amount = _amount;
    }
    string from;
    string to;
    string amount;

    public string From {get{return from;}}
    public string To   {get{return to;}}
    public int    Amount {get{return amount:}}
}
```
이렇게 말이다. 근데 아까 get만 써주면 읽기 전용이 된다면서요? 

맞다 맞는데 왜 이게 따로 있냐하면은, get은 오직 클래스(생성자) 내부에서만 값을 할당할 수 있다. new Character {CreateTime = ...} 과 같이 식으로 값을 넣는 것이 불가능하다.

클래스 밖에서는 생성할 떄조차 값을 건들릴 수 없기 때문이다.

하지만 init을 쓰면 set과 같이 외부에서 프로퍼티를 변경할 수 있다. 하지만 객체 초기화할 때만 프로퍼티 변경이 가능하다. 

public string Name {get; init;} 이렇게 프로퍼티를 선언하면 초기화 전용 자동 구현 프로퍼티가 된다. 이제 해당 프로퍼티는 생성자가 없어도 외부에서 값을 받아 초기화하고 값이 변경되지 않는 읽기 전용 프로퍼티가 된다.

맙소사 이로서 내 코드가 더 짧아 질 수가 있다. 만약 이름과 직업을 한번 정하면 바꿀수 없는 설계의 게임이라면 말이다. [예제04](04_Init.cs) 

### 프로퍼티 초기화를 강제하는 required 키워드 
init은 프로퍼티를 객체 초기화 시에만 값을 할당할 수 있게 해주지 딱히 강제는 아니다. 그래서 깜빡하고 초기화를 하지 않을 수도 있다.

required 한정자를 수식 한다면 프로퍼티를 객체가 초기화될 때 반드시 초기화되도록 컴파일 수준에서 강제한다.

프로퍼티 이름 앞에 사용한다. 사실 이건 내용이 이게 다라서 따로 예제는 만들지 않겠다. 어떻게 쓰는지만 보자 
```c#
class BirthdayInfo
{
    public required string Name {get; set;}
    public required DateTime Birthday {get; init;}
}
//이렇게 선언 해줬다면 나중에 객체를 생성할 때
    BirthdayInfo birth = new BirthdayInfo{Name = "서현", Birthday = new DateTime(1991, 6, 28)};
//이렇게 반드시 값을 할당해줘야한다.
```

### 레코드 형식으로 만드는 불변 객체 
불변객체는 내부 상태(데이터)를 변경할 수 없는 객체를 말한다. 일단 불변 객체를 만드는 법부터 알아보자, 먼저 클래스의 모든 필드를 readonly로 선언하면 된다. 값 형식은 readonly struct로 
구조체를 선언하면 된다. 

7장에서 잠깐 깊은 복사와 얕은 복사이야기가 나온적이 있다. 클래스는 참조 형식이라 그냥 객체가 참조하는 메모리 주소만 복사하게 된다. 그래서 클래스의 깊은 복사는 new 키워드를 통해 객체를 생성하고 그곳에 하나 하나 직접 가져왔어야 했다. 

반대로 값 형식 객체는 다른 객체에 할당할 때 깊은 복사를 수행한다. 직접 우리가 구현할 필요가 없이 1:1로 필드를 복사해온다. 

하지만 필드수가 많아지거나 객체를 여러 곳에서 사용해야하는 경우 비용이 커진다.  반면에 클래스(참조 형식 객체)는 메모리 주소만 복사하기에 이런 비용문제가 덜하다.

또한 객체를 비교할 때 기본적으로 값 형식은 모든 필드를 1:1로 비교한다. 참조 형식은 우리가 직접 비교 코드를 써줘야한다. (Equals() 메소드를 오버라이딩함 보통) 

아무튼 말하고자 하는 바는 값 형식은 비용 문제가 있지만 우리가 사용하기에 편하다. 참조 형식은 비용 문제가 없지만 우리가 직접 구현해야기에 불편하다. 

이러한 둘의 장점을 얻을 수 있는 방법이 있다.

그 전에 공부하다가 의문이 든 점이 있다. 결국 참조 형식을 깊은 복사를 한다는 건 힙에 공간을 새로 만들어야 한다는 거 아닌가? 깊은 복사를 하는 코드 길이만 차이나지 비용은 같지 않나? 

결론부터 말하자면 같지는 않고 참조 형식의 깊은 복사가 더 비싸다. (이게 무슨 말이야?)

#### 값 형식의 복사 (스택 - Stack)

값 형식의 복사는 스택 영역에서 일어난다. 스택은 데이터를 쌓고 빼는 모양이라 복사가 일어나면 스택 포인터만 살짝 이동시켜 공간을 확보하고 데이터를 통째로 복사 해온다.

CPU 레벨에서 처리되기 때문에 속도가 매우 빠르고 할당에 드는 오버헤드가 거의 없다.

#### 참조 형식의 깊은 복사 (힙 - Heap)
참조 형식을 깊은 복사하려면 new 키워드를 사용해 힙(Heap) 영역에 새로운 객체를 만들어야 한다.

메모리 어딘가에 객체가 들어갈 만한 넉넉한 '빈 공간'을 탐색해야 하고, 메모리 할당표를 갱신하는 등 훨씬 복잡하고 느린 동적 할당 과정을 거친다. 

심지어 값 형식은 해당 코드 블럭이 끝나면 알아서 소멸되지만 참조 형식은 나중에 가비지 컬렉터가 따로 치워주어야 한다. 

그럼 책이 틀린건가? 

그건 아니다. 책에서 이야기 한 것은 값 형식의 복사(깊은 복사) 와 참조 형식의 복사(얕은 복사)를 비교해서 이야기 한 것이다. 즉 단순 할당을 이야기 한 것이다. 

이제 오해도 풀렸으니 이 관점에서 다시 요약하자면 값 형식은 비교를 수행하기에는 적합하지만 비용이 비싸다, 반면 참조 형식은 비용은 저렴하지만 비교를 위해 매번 구현 코드를 짜야하는 불편함이 있다. 

그래서 나온게 레코드다. 참조 형식이지만 값처럼 비교하고 불변성을 보장한다. 이제 진짜 레코드를 알아보자 

#### 레코드 선언하기 
record 키워드와 초기화 전용 자동 구현 프로퍼티를 함꼐 이용해서 선언한다. 

주의할 점은 레코드에는 초기화 전용 자동 구현 프로퍼티 뿐만 아니라 쓰기 가능한 프로퍼티와 필드도 자유롭게 선언해 넣을 수 있다.

```c#
record RTransaction
{
    public string From {get; init;}
    public string To   {get; init;}
    public string Amount {get; init;}
}
```
이렇게 선언한 레코드로 인스턴스를 만들면 불변 객체가 만들어진다. 당연하지만 init을 써서 선언했으니 객체 생성할때 값을 다 넣어줘야한다.

### with를 이용한 레코드 복사 
c# 컴파일러는 레코드 형식을 위한 복사 생성자를 자동으로 작성한다. 근데 이게 protected로 선언되기 때문에 명시적으로 호출이 안된다.

왜 protected로 선언되는데요?

일단 레코드도 상속이 가능하다. 만약 부모 레코드를 상속받은 자식 레코드가 있으면 부모 레코드의 데이터를 안전하게 복사되어야 한다. 

protected는 자식 클래스까지만 이 복사 로직에 접근할 수 있게 하여 외부에서 잘못된 방식으로 객체를 복사하는 것을 막아준다. 

또한 with 키워드 만으로 접근가능하게 하여 안전하게 시스템이 처리하게 하기 위해서다. 한마디로 복사 과정의 무결성을 보장하기 위해서다.
