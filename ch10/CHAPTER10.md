프로그램을 작성하다 보면 같은 성격을 띤 다수의 데이터를 한 번에 다뤄야 하는 경우가 자주 생긴다.

### 배열 분할하기 
Array.Copy()는 배열의 일부를 다른 배열에 복사하는 기능으로 나쁘지 않았지만 다른 방법도 있다.

System.Range라는게 있는데 시작 인덱스와 마지막 인덱스를 이용해서 범위를 나타낸다. 예시를 보자 

```c#
System.Range r1 = 0..3; // 이걸 [] 사이에 인덱스 대신 넣으면 분할된 배열이 반환된다.
int [] sliced = scores[r1]; // 배열이 나온다.

int[] sliced2 = scores[0..3]; // 이렇게 직접 .. 연산자를 넣으면 더 간결하다.
```
이렇게 .. 연산자를 쓴다. 왼쪽은 시작 인덱스, 오른쪽은 마지막 인덱스가 오는데 주의 할 점이 있다. 

시작인덱스는 포함되어 분할 결과에 나오지만 마지막 인덱스는 제외된다. 0..3 이면 0,1,2 인덱스만 나온다는 말이다. 왜요?

반개구간 표기법이란게 있는데 이거랑 같은 설계이기 때문이다. 그냥 마지막 인덱스는 항상 제외된다! 라고 알아두면 문제가 없을 것이다.

### 다차원 배열 
아까 말했듯이 2차원이 있으면 3차원 4차원도 있을 것이다. 이걸 다차원 배열이라한다. 차원이 둘 이상인 배열말이다. 차원이 늘어날수록 요소에 접근 할 때 사용하는 인덱스의 수가 늘어나는 점만이 다를 뿐이다.

사실 3차원 배열까지만 가도 상상하기가 어렵다. 한번 종이에 대고 그려봐라 3차원까지는 그렇다 치지만 4차원부터는 감도 안 잡힌다. 

어디서 본건데 그래서 3중 for문을 넘어가기 시작하면 그거는 잘못된 코드라고 했었다. 

유지보수가 어려워지고 대부분의 경우 데이터 구조 설계를 다시 해야한다는 신호이다. 

그럼 선언을 어떻게 하는지 보고 바로 예제로 넘어가자 3차원 같은 복잡한 구조는 선언을 할때 명시적을 크기를 지정해주는게 좋다. 

그래야 나도 안 헷갈리고 컴파일러가 초기화 코드와 선언문에 있는 배열의 차원 크기를 비교해서 이상이 없는지 검사해줄 수 있다.

### 가변 배열 
이제까지 우리는 2차원 배열의 요소에 접근할 때 첨자 두 개를 사용해야 했다. 하나만 사용해서 1차원 배열에 접근하거나 하는 것은 불가능 했다.

가장 큰 차이점은 행마다 열 수를 다르게 줄 수 있다는 점이다. 

가변 배열은 이러한 다차원 배열과 달리 배열을 요소로 사용해 접근할 수 있다. 

```c#
데이터_형식[][] 배열_이름 = new 데이터_형식[가변_배열의_용량][];

int[,]  → 다차원 배열. 모든 행의 열 수가 같음
int[][] → 가변 배열. 행마다 열 수가 달라도 됨
```
이런 형식으로 선언을 한다.  이어서 초기화 시키는 법도 보자
```c#
int[][] jagged = new int[3][];
jagged[0] = new int[5] {1,2,3,4,5};
jagged[1] = new int[] {10,20,30};
jagged[2] = new int[] {100,200};
```
이렇게 선언과 동시에 초기화가 가능하다.  이제 예제를 보자 딱히 생각나는게 없어서 클로드 한테 상황을 달라고 했다. [예제06](06_JaggedArray.cs) 

### 컬렉션 
컬렉션이 뭐죠? 같은 성격을 띤 데이터의 모음을 담는 자료구조를 말한다. 

배열도 .Net에서 제공하는 다양한 컬렉션 자료구조의 일부이다. .Net이 제공하는 컬렉션들이 무조건 상속해야 하는 ICollection 인터페이스를 상속하고 있기 때문이다.

배열 말고도 다양한 컬렉션 클래스들이 있는데 그중에 4가지를 보자(ArrayList, Queue, Stack, Hashtable) 

#### ArrayList 
ArrayList는 가장 배열과 닮은 컬렉션이다. 사실 배열의 가장 큰 불편한 점이 뭔가? 그건 바로 크기를 미리 정해둬야한다는 점이다. 

이 컬렉션을 쓰면 미리 용량을 지정할 필요 없이 필요에 따라 자동으로 그 용량을 늘리거나 줄어든다. 

앞서 말했듯이 이것들은 클래스로 정의 되어 있다. 그 말은 즉 메서드들을 달고 있다는 말이다. 가장 중요한 메서드 3가지가 있다.

Add(), RemoveAt(), Insert() 영어를 배웠다면 대충 예상이 갈거다 무슨 기능인지 

```c#
ArrayList list = new ArrayList();
list.Add(10); // Add는 가장 마지막에 있는 요소 뒤에 새요소를 추가한다. 
list.Add(20);
list.Add(30);
list.RemoveAt(1); //20을 삭제
list.Insert(1,25); //25를 1번 인덱스에 삽입한다. 그럼 10 25 30이 저장되어 있겠죠?
```
간단하다. 교제에 나오는 예제를 그대로 보기전에! 사실 이건 좀 낡은 방식이다. 

#### ArrayList 대신 List<> 
제네릭이란게 c#에 도입되고 나서부터 도입된건데 제네릭은 나중에 알아보고 ArrayList말고 왜 List<>를 쓰라고 하냐?

일단 ArrayList는 선언할 때 타입을 지정 하지 않는다. 그래서 뭐든 들어가지만 꺼낼 때마다 명시적으로 형변환을 해줘야한다. 

그렇다 보니 박싱/언박싱이 일어나 속도가 저하되기도 한다. 

 (박싱: 값 형식을 object로 포장해 힙에 올리는 것. 언박싱: 다시 값 형식으로 꺼내는 것. 이 과정에서 힙 할당이 발생해 느려진다.)

그건 알겠는데요 제네릭이 뭐에요? 그건 나중에 일반화 프로그래밍을 할때 이야기해주겠다. 바로 다음 챕터이다. 

```c#
// ArrayList — 꺼낼 때 형변환 필요
int n = (int)list[0];

// List<int> — 그냥 꺼내면 됨
int n = list[0];
```

#### Queue
큐는 대기열을 이야기한다, 데이터나 작업을 차례대로 입력했다가 입력된 순서대로 하나씩 꺼내 처리하기 위해 사용된다. 

가장 큰 특징은 선입선출 입력은 뒤에서 출력은 앞에서만 이루어진다는 점이다. 이걸 FIFO 한다. 이걸 어따 쓰는데요?

OS에서 CPU가 처리해야 할 작업을 정리할 때, 프린터가 여러 문서를 출력할 때 등등 수도 없이 많이 쓰인다. 

게임 개발에 관련해서도 다양하게 사용가능하다. 몬스터 스폰 순서라던가 테트릭스에서 블럭을 꺼내줄때 라던가 말이다.

자 자세히 살펴보자 

일단 선언 방법은 이렇고 원 큐에 넣고 빼는 법 보자 
```c#
Queue que = new Queue(); //이 친구도 object형으로 어떤 형이든 넣을 수 있는데 제네릭이 따로 존재한다.
que.Enqueue(1); // 이렇게 요소를 추가한다. Enqueue() 메소드를 이용해서 말이다.
que.Dequeue(); // 이렇게 요소를 뺀다. Dequeue() 메소드를 이용해서 말이다. 
```
반드시 알아야 하는게 선입선출이기 때문에 요소를 추가하면 가장 뒤에 추가가 되고 Dequeue()를 써서 요소를 빼낼때에도 가장 앞에 있는 요소가 빠져나온다. 

그리고 Peek() 메서드를 쓰면 앞에 있는 요소를 확인만 하고 제거하지는 않는다.

마찬가지로 이 친구도 제네릭이 따로 있다. 

```c#
Queue<int> que = new Queue<int>(); // 제네릭 버전 권장
```

#### Stack
이건 큐랑 반대로 먼저 들어온 데이터가 나중에 나가고 (First In - Last Out), 나중에 들어온 데이터는 먼저 나가는 (Last In - First Out) 구조의 컬렉션이다.

데이터를 넣을 때는 Push() 메소드를 이용하고, 꺼낼 때는 Pop() 메소드를 이용한다. 말그대로 상자를 쌓고 다시 꺼낸다는 느낌으로 이해하자 

게임에서는 실행 취소(Undo) 기능, 던전 입장/퇴장 기록, 메뉴 화면 이동 히스토리 등에 활용된다.

Pop()을 호출하여 데이터를 꺼냈다면 그 데이터는 컬렉션에서 제거되고 그 아래에 있던 데이터가 가장 위로 올라온다. 어떻게 하는지 바로 보자

```c#
Stack stack = new Stack();
stack.Push(1); //최상위 데이터는 1
stack.Push(2); //최상위 데이터는 2
stack.Push(3); //최상위 데이터는 3

int a = (int)stack.Pop(); // 최상위 데이터는 다시 2
int b = (int)stack.Peek(); // 제거는 안하고 확인만 
```
예제는 넘어가자 어차피 일반화 프로그램을 할때 다시 할건데 그때 업그레이드 된 버전으로 한번에 보겠다. 앞에서도 나왔지만 자료형을 명시해 형변환이 필요하냐 안하냐의 차이다. (물론 다른차이도 있다.)

#### Hashtable
딕셔너리의 전신이라고도 볼 수 있겠다. 키와 값의 쌍으로 이루어진 데이터를 다룰 때 사용한다. 제네릭에서 딕셔너리라고 하듯이 사전 같은 친구다.

내가 이걸 처음봤을 때에는 2D 타일맵에서 타일 정보를 저장하기 위해 사용했었다. (좌표가 키 값 해당 타일의 정보가 벨류) 

탐색 속도가 빠르고 사용하기가 편하다. 다음과 같이 사용하겠다.
```c#
Hashtable ht = new Hashtable();
ht["book"] = "책";
ht["cook"] = "요리사";
ht["tweet"] = "지저귀다";

Console.WriteLine(ht["book"]);
Console.WriteLine(ht["cook"]);
Console.WriteLine(ht["tweet"]);
```
보다시피 배열고 비슷하다. 다만 데이터를 저장할 요소의 위치로 인덱스를 사용하는게 아니라, 키 데이터를 그대로 사용한다는 점이 차이가 있다.

또한 키 데이터로 자료를 찾기때문에 탐색 속도가 거의 소요되지 않는다. (이를 해싱이라고 하는데 이는 알고리즘 이므로 따로 공부가 필요하다.)

### 컬렉션을 초기화하는 방법 
우리가 선언하는 방법은 익히고 메소드도 몇개 익혔는데 뭔가 뺴 먹었다. 그렇다 초기화하는 방법이다.
```c#
int[] arr = {123, 456, 789};

ArrayList list = new ArrayList(arr); //123, 456, 789
ArrayList list2 = new ArrayList() {11, 22, 33}; // ArrayList는 배열의 도움 없이 직접 컬렉션 초기자를 이용해 초기화할 수 있다, 
Stack stack = new Stack(arr); // 789, 456, 123 스택은 제일 마지막에 들어간 요소가 최상위 요소가 된다. 
Queue queue = new Queue(arr); // 123, 456, 789
```
Stack과 Queue는 컬렉션 초기자를 이용할 수 없다. 이 두 컬렉션은 IEnumerable 라는 인터페이스를 상속하지만 Add() 메소드를 구현하지 않았기 때문이다.

### 인덱서
인덱서는 인덱스를 이용해서 객체 내의 데이터에 접근하게 해주는 프로퍼티라고 생각하면 된다. 객체를 배열처럼 사용할 수 있게 해준다.
```c#
class 이름
{
    한정자 인덱서_형식 this[형식 index] //index말고 다른 적당한 이름 써도 됨
   {
        get
        {
            //index를 이용하여 내부 데이터 반환
        }

        set
        {
            //index를 이용하여 내부 데이터 저장
        }
   }
}
```
생긴것도 프로퍼티랑 똑같지 않는가 다만 다른 점은 프로퍼티는 이름을 통해 접근하게 해준다면 인덱서는 인덱스를 통해 객체 내 데이터에 접근하게 해준다. 

내부적으로도 똑같이 동작한다. 그럼 인덱스를 넘어나게 값이 들어오면 어떻게 하느냐? 아래의 예제를 보자 
```c#
class Program
{
    private int[] array;

    public Program()
    {
        array = new int[3];
    }

    public int this[int index]
    {
        get
        {
            return array[index];
        }

        set
        {
            if(index >= array.Length)  // 인덱스가 배열의 크기를 벗어나면 인덱스에 맞춰 배열의 크기를 조정한다. 
            {
                Array.Resize<int>(ref array, index + 1);
                Console.WriteLine("Array Resized : {0}", array.Length);
            }
            array[index] = value;
        }
    }
 static void Main()
 {
     Program obj = new Program();
     obj[0] = 10;
     obj[5] = 60;  // 범위 초과 → Array Resized : 6 출력 후 저장
     Console.WriteLine(obj[5]);  // 60
 }
}
```
