# 챕터 8은 인터페이스와 추상 클래스 관련 내용이다.

사실 작년 즈음인가 공부하다가 기본 문법정도만 때고 학교 공부하랴 훈련소 갔다오랴 하며 쭉 안했었는데 공익 생활 하면서 게임 만들어보니깐 모르는게 너무 많았다. 

특히 인터페이스는 아예 뭔지도 몰라서 책을 다시 거의 반년만에 폈는데 클래스 내용도 읽어보니깐 모르겠어서 복습차원으로 쭉 공부하고 드디어 인터페이스 파트다.

아무튼 인터페이스는 뭐냐? 생긴건 일단 클래스랑 비슷하다. interface 키워드를 이용해서 선언한다.

메소드, 이벤트, 인덱서, 프로퍼티만을 가질 수 있다.  이게 뭔데요? 나중에 알아보자 적어도 메소드는 뭔지 아니깐 

인테페이스는 접근 제한 한정자를 사용할 수 없고 모든 것이 public으로 선언된다. 그리고 메소드 이벤트 등만 가질 수 있다 했는데 그마저도 구현부가 없다.

인터페이스는 인스턴스를 가질 수 없지만 이 인터페이스를 상속받는 클래스의 인스턴스를 만드는 게 가능하다. 물론 규칙이 있다. 파생 클레스는 인터페이스에 선언된 모든 메소드를 구현해줘야 한다.

이 메소드들은 public 한정자로 수식해야한다. 간단한 예제를 보고가자 [예제1](01_InterfaceEx.cs)

예제 처럼 interface 키워드로 선언 그리고 내부에 구현할 메소드 이름과 매게변수만 써 놓고 해당 인터페이스를 상속 받는 클래스에서 메소드를 구현하는 흐림인걸 보았다.

인터페이스는 인스턴스르 못 만들지만, 참조를 만들 수 있다. 이 참조에 파생 클래스의 객체의 위치를 담는 것이다. 파생 클래스는 기반 클래스 와 같은 형식으로 간주되듯이 

인터페이스와 클래스 관계에도 적용된다.
