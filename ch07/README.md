# 챕터 7은 클래스에 대한 파일이다. 

클래스를 알기전에 객체지향 프로그래밍에 대해 알아야 한다. OOP라고도 하는데 코드 내 모든 것을 객체로 표현 할려는 프로그래밍 패러다임이다.

코드를 작성 할 때 모든 것을 다 표현할 필요는 없다. 객체의 주요 특징만 뽑아내면 된다.

그럼 객체의 가장 주요한 특징은 무엇일까?
바로 속성과 기능이다. 예를 들어 사람은 속성으로 피부색, 키, 몸무게 등이 있다. 기능으로 걷고 뛰고 먹고 자는 행위가 그 예시가 되겠다.

그럼 코드로 이 것들을 어떻게 표현 할 수 있을까? 속성은 데이터로, 기능은 메소드로 표현하면된다. 즉 객체는 데이터와 메소드로 이루어진다고 할 수 있다.

그래서 클래스는 뭔가요?

클래스는 객체를 만들기 위한 청사진이다. 클래스가 자동차 설계도라면 객체는 생산된 실제 자동차라고 비유 할 수 있다. 설게도에는 변경 가능한 속성(요소)들과 변경 불가능한 속성이 있다. 또한 설계도(클래스)는 실체가 없지만 이를 보고 만든 자동차는 실체를 가지고 기능(메소드)를 실행한다. 

우리가 자료형 변수를 만들때 쓰는 string도 이미 정의된 클래스이다. 그 뒤에 붙는 변수명은 객체이다. 참고로 객체를 인스턴스라고 부르기도 한다. 
아무튼 이런 식으로 객체에서 뽑아낸 속성과 기능을 클래스 안에 변수와 메소드로 표현 된다. 이런 식의 프로그래밍을 객체지향 프로그래밍이라고 한다.

클래스는 복합 데이터 형식이다. 클래스는 객체를 위한 청사진인 동시에 여러 메소드를 묶는 집합이다. 또한 코드에서 보는 클래스는 또 하나의 데이터 형식이다.
기본 데이터 형식을 조합해서 만든다는 말이다. 그리고 복합 데이터 형식은 참조 형식이다. 

* 클래스를 생성할 때에는 class 키워드와 클래스_이름을 이용해서 선언한다. 
* 클래스에서 선언되는 변수를 필드라고 한다. 그리고 필드와 메소드 프로퍼티 이벤트 클래스 등 클래스 내에 선언된 모든 요소를 멤버라고 한다.
* new 연산자와 생성자를 이용해 힙(Heap)에 객체를 생성하고, 스택(Stack)에 있는 참조 변수가 힙에 생성된 객체의 주소를 가리킨다.
 
클래스의 선언과 객체의 생성은 EXclass.cs 파일을 참고하자.

### 생성자와 종료자 
생성자는 클래스를 선언할 때 명시적으로 생성자를 구현하지 않아도 컴파일러가 알아서 만들어준다. 이걸 기본 생성자라고 한다.

그럼 왜 직접 구현해야 하는 가?

객체를 다루다 보면 객체를 생성하는 시점에 객체의 필드를 원하는 값으로 초기화하고 싶을 때가 있다. 
즉 매개변수를 입력받아 원하는 값으로 필드를 초기화할 수 있는 최적의 장소가 바로 생성자이다. 

생성자는 클래스와 이름이 같고 반환 형식이 없다. 해당 클래스의 객체를 생성하는 역할 뿐이기 때문이다. 
참고로 생성자를 이용해 객체를 생성할 때에는 매개변수의 수와 형식이 일치해야한다. 

생성자 예시로 넘어가서 보자 Cat.cs 파일을 참고하면 된다.

다음으로 종료자에 대해 이야기 하면 종료자의 이름은 클래스 이름 앞에 ~을 붙이면 된다.

생성자와 매개변수도 없고 한정자도 없다. 또한 여러 버전의 종료자를 만드는 오버로딩도 불가능하며 직접 호출할 수도 없다. 

그럼 어떻게 쓰냐?

CLR의 가비지 컬렉터가 객체가 소멸되는 시점을 판단해서 종료자를 호출 해준다. 그래서 유니티나 일반적인 C# 환경에서는 프로그래머가 직접 종료자를 구현할 일이 거의 없다. 오히려 잘못 쓰면 가비지 컬렉터의 동작을 방해해서 게임에 렉(프레임 드랍)을 유발하기도 한다. 따라서 종료자 예제는 넘어간다.

### 정적 필드와 메소드
static 메인 클래스에도 붙는 키워드라 익숙하다. 사전적 의미로는 정적이라는 뜻이다. 메소드나 필드가 클래스의 인스턴스가 아닌 클래스 자체에 소속되도록 지정하는 한정자이다.

저게 무슨 말이냐 한 프로그램 안에서 인스턴스는 여러 개가 존재 가능하다. 하지만 클래스는 단 하나만 존재한다. 똑같은 클래스는 두 개 이상 존재할 수 없다. 

어떤 필드가 클래스에 소속된다는 것은 곧 그 필드가 프로그램 전체에서 유일하게 존재한다는 것을 의미한다. 

그럼 뭐가 다르고 뭐가 좋냐? 

static이 붙은 필드는 프로그램 전체가 공유하고 별도의 인스턴스 생성 없이 클래스.변수명 으로 즉시 접근이 가능하다. 정적 메소드도 마찬가지고 

비정적 메소드는 인스턴스 메소드라고 한다. 보통 객체 내부 데이터르 이용해야 하는 경우는 인스턴스 메소드 내부 데이터를 이용할 일이 없는 경우에는 메소드를 정적으로 선언한다. 

그리고 static 키워드가 붙은 멤버나 클래스는 프로그램이 실행될 때 프로그램이 끝날 때까지 유지되는 별도의 특수한 메모리 영역(Static 영역)에 자리를 잡는다. (그래서 전역에서 접근이 가능함) 그리고 참고로 static을 붙여 클래스를 선언 하면 그 아래 모든 맴버들에게도 static 키워드를 붙여줘야 한다.
